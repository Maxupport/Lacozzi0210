# 專案風險清單

> 狀態：草案，等待專案負責人確認。

## 評級方式

- P0：可能立即危及帳號、資料或正式站，優先處理。
- P1：可能阻礙安全發布或造成重要功能故障。
- P2：會增加維護成本、效能問題或使用者困擾。
- P3：改善項目，短期不影響正常運作。

## 風險處理原則

- P0 在其他優化以前處理。
- P1 必須在大規模內容或功能擴充以前完成。
- P2 分批納入相關工作，不建立大型重構專案。
- P3 必須有明確效益，不以追求分數為唯一目的。
- 任何處理若造成更高風險，先停止並重新拆分。

---

## 目錄用途

- **任務規格傳遞**：提供標準化、結構化的任務指引，明定各任務的修改範圍、驗收條件、禁止事項與回復機制。

- **可重複使用範本**：提供標準任務範本，確保後續任務派發的一致性與安全性。

## AG 任務標準執行流程

每次執行工程任務時，皆依循以下標準步驟：

1. **任務建立**：Codex 複製 [AG 任務範本](./AG-TASK-TEMPLATE.md) 為新檔案（命名為 `AG-XXX-<簡稱>.md`），填入完整規格、允許範圍與停止條件。**嚴禁直接覆寫範本檔案**。
2. **分支準備**：從最新 `origin/main` 建立短期工作分支（命名為 `ag/<主題名稱>`）。
3. **前置閱讀**：AG 閱讀 `AGENTS.md`、相關架構文件與 Next.js 16 本機說明文件（位於 `node_modules/next/dist/docs/`）。
4. **自主執行**：AG 僅在授權的「允許修改範圍」內動工，嚴禁自行擴大範圍或順便重構。
5. **本地驗證**：在 `la-cozzi-website/` 目錄執行 `npm run typecheck`、`npm run lint`、`npm run build`、`npm run test:smoke`，並以 `git diff --check` 確認格式。
6. **交付與 PR**：Commit 並推送至 GitHub 建立 Pull Request。**AG 嚴格禁止自行合併至 `main`**。
7. **Codex 審查**：AG 提交結構化回報後停止操作，交由 Codex 審查完整 Git diff、CI 檢查結果與 Vercel Preview。
8. **核准與發布**：專案負責人核准後合併至 `main`，並執行線上煙霧測試與發布確認。

## 核心治理原則

1. **歷史紀錄保留**：已完成的任務文件（如 AG-001）必須完整保留於本目錄中，作為後續維護、架構溯源與決策依據，不得任意刪除或覆寫。
2. **範本複製原則**：建立新任務時必須另存新檔，嚴禁直接編輯或覆寫 `AG-TASK-TEMPLATE.md`。
3. **嚴禁機密洩漏**：所有任務文件均會進入 Git 儲存庫，**嚴格禁止包含任何密碼、Token、Cookie、私密金鑰或資料庫連線字串**。需要環境變數時僅得記錄變數名稱與用途。
